PhysiGuard live battery integrity simulation

01 / Normal drive

Start a live run.

Choose a backend scenario and start it. Temperature, state estimates, detection evidence, and response state update from the live session.

The selected seed makes the backend simulation reproducible.

Start from the run bar

02 / Intrusion

The selected scenario begins.

The backend runs the selected attack model and streams protected, unprotected, reported, and estimated battery values into this scene.

Use the scenario selector and attack controls to explore the API session.

03 / Vehicle response

Evidence accumulates.

The HUD uses estimator and detector values sent by the backend. Scene color follows its live response state.

Temperature limits and margins come from the configured backend run.

04 / Detection

The defense responds.

Passive evidence, active probes, and the command guard contribute to the backend's detection and response state.

The event log lists backend events as they arrive.

05 / Digital twin

Follow the protected estimate.

The wireframe marks the protected estimator and response state during a confirmed event.

Estimate values and control mode update from live frames.

06 / Response

The backend contains unsafe requests.

When its guard enters safe mode, the backend constrains charging current and continues to report the simulation state.

Current request, guarded command, and safety margin are available in the live session.

07 / Review

Review and repeat the run.

Backend frames drive the chart and event log. Start again with the same seed or choose another scenario.

All values are simulated; this prototype is not connected to a real vehicle.

End of run

What the simulation showed.

Backend-generated telemetry, detection evidence, and response state drive the 3D scene. The chart and event log use the same live session frames.

Detection

A state estimator checks battery telemetry against its physical model. Passive evidence and keyed active probes contribute to detection.

Response

The command guard constrains unsafe current requests and enters safe mode after sufficient evidence.

Limits

This is a simulated research prototype, not a vehicle interface. No hardware is connected and no real telemetry is read.
